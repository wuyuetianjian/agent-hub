# 跨平台 Agent 悬浮工具：需求与设计草案

日期：2026-10-24。状态：用户已确认设计；开发版实现与本地构建已完成，接入及验证范围见 docs/providers.md 和 docs/validation.md。

## 1. 已确认需求

- 同时支持 macOS、Windows 和 Linux。
- 提供桌面悬浮窗，监控用户本人已登录的主流 Agent 账号额度。
- 在悬浮窗处理 CLI 的权限确认、选项选择和文本回复。
- 主流 Agent 均有独立入口和图标；提供可扩展的适配器目录。
- 所有变更纳入 Git；实现前先更新 docs，README 保留中文和 English。
- 配置优先级为数据库、服务/进程配置、可外置挂载的配置文件；源码不写死配置、凭据、服务 URL 或本机路径。

## 2. 首版产品范围

应用由常驻后台、紧凑悬浮窗、展开详情窗和系统托盘组成，数据保存在本机。

悬浮窗按用户选择的顺序展示 Agent 图标、名称、账号、剩余额度、重置倒计时及待确认数量。支持拖动、置顶、折叠、隐藏和从托盘恢复；多显示器变化后修正不可见窗口位置。默认不抢占输入焦点，用户点击确认卡片后再进入交互。

展开窗口显示全部 Agent、数据来源、更新时间、多个额度周期、正在运行的会话和确认队列。设置中可以调整显示项、刷新频率、告警阈值、CLI 路径、配置目录、主题、语言、开机启动及窗口行为。初始界面提供中文和 English。

首批目录包含 Claude Code、Codex、Gemini CLI、Google Antigravity、Cursor、GitHub Copilot、Windsurf、Cline、Roo Code、OpenCode、Continue、Kiro、Amazon Q Developer 和 Aider。这里的“目录覆盖”与“额度接口已经可用”分别验收，不能仅放图标就宣称已完成账号接入。

每项使用可合法分发的官方图标资源，随应用打包并登记来源及授权信息。适配器元数据引用图标资源，用户可以用本地图标覆盖。不能合法分发的品牌资源使用清晰可辨的通用图标并标注产品名称，不伪造官方标识。图标始终配合文本名称和无障碍标签，离线可显示。

### 追加交互需求（用户于实现阶段提出）

- macOS 新增可选的灵动岛样式：顶部居中黑色紧凑区域，展示 Agent 图标及摘要额度；普通悬浮窗仍可切换。无刘海屏也支持顶部样式，具体位置受屏幕安全区约束。
- 点击任意 Agent 图标展示该 Agent 的账号、全部额度周期、重置时间和相关会话。
- 默认摘要按最短额度周期选择：有 5 小时周期时展示 5 小时剩余额度；其余周期保留在详情。另提供“剩余比例最低”选项，便于不同使用偏好。未知值不能被选成 0%。

## 3. 技术方案选择

推荐 **Tauri 2 + React/TypeScript + Rust + SQLite**：适合长期驻留的小窗口，前端负责展示，Rust 负责进程、协议、系统集成和本地数据。采用系统 WebView，需分别验证三平台显示差异。具体资源占用以实测为准。

备选 **Electron + React/TypeScript + SQLite**：Node 生态对终端和 CLI 接入方便，界面运行时更统一；需要随应用分发 Chromium，常驻资源预算需单独评估。

备选 **Qt + Python/PySide**：桌面组件和进程交互直接，但 Python 运行时分发、界面样式和跨平台打包需要额外维护。

已确认采用推荐的 Tauri 2 技术栈。

## 4. Agent 适配方式

统一适配器负责发现安装、识别账号、报告能力、采集额度和接收/回应交互。额度采集与会话控制相互独立：能查额度不代表能控制该产品的所有会话。

适配器能力包含：账号识别、订阅额度、API 用量、重置时间、托管 CLI、外部会话桥接、权限确认、单选/多选、文本回复。每项能力分别报告支持状态及原因。

### Codex

- 优先通过本机 `codex app-server` 的 `account/read`、`account/rateLimits/read` 及更新事件读取已登录账号和限额。
- 通过 app-server 的请求 ID 关联命令执行、文件修改、权限申请和用户输入，不将“已发送回复”误判为“命令执行成功”。
- API Key 登录与 ChatGPT 订阅登录分别展示，接口未提供的订阅额度保持未知。
- 根据已安装版本协商协议；本机已检测到 codex-cli 0.163.0，但尚未查询个人账号或额度。

### Claude Code

- 利用官方 status line 的 `rate_limits` 采集额度窗口和重置时间。该字段依赖账号类型和会话活动；没有新数据时保留带时间戳的快照并标记过期。
- 通过 `PermissionRequest` Hook 处理可支持的权限确认；问题回复按工具的实际输入结构接入。
- 现有 status line 和 Hook 配置必须保留、合并并支持恢复；覆盖前展示变更内容。
- 对未经过该 Hook 的提示保留 CLI 原始交互入口；不承诺所有提示均可通过同一 Hook 回答。
- 本机已检测到 Claude Code 2.1.302，但尚未读取账号凭据。

### Gemini CLI 与 Google Antigravity

- 两者使用独立适配器和图标，按实际安装、账号资格和返回能力识别。
- Gemini CLI 可通过 ACP 建立托管会话；权限请求按所协商 ACP 版本处理，不能把一般 BeforeTool Hook 等同于权限批准接口。
- Gemini CLI 的 `/stats model` 提供额度查看入口，源码包含 `retrieveUserQuota`。内部服务调用不视为稳定公共 API，必须绑定已验证版本和账号类型。
- 官方 2026-06-18 公告说明个人免费、AI Pro、AI Ultra 账号转向 Antigravity CLI；企业 Code Assist 和 API Key 路径保留。部分认证/额度页面仍描述旧路径，不能据此保证个人账号继续可用。
- Antigravity 的额度读取和交互控制必须单独验证；不得用 Gemini API Key 的统计替代个人订阅额度。
- 当前环境未检测到 Gemini CLI，因此本次文档调研不等于真实账号联调完成。

### 其他首批 Agent

- Cursor、GitHub Copilot、Windsurf、Kiro、Amazon Q Developer：分别核实登录身份、账号/套餐用量和可用的 CLI 或扩展接口，不假定统一的额度窗口。
- Cline、Roo Code、OpenCode、Continue、Aider：识别所连接的模型供应商；使用自有 API Key 时展示来源明确的用量/成本，并在供应商确实提供限额时展示限额。
- 各产品独立实现并验证适配器。未具备可用接口时显示“该账号类型暂不支持读取”及操作入口，不能显示模拟剩余量或将未实现状态标成已接入。
- 新 Agent 由注册表元数据及适配器扩展，界面无需为每个产品复制一套逻辑。

## 5. CLI 交互设计

已确认首版由小工具启动并管理 CLI 会话，支持通过配套启动器和可用的官方 Hook 加入桥接。

按供应商优先使用结构化协议或官方 Hook。需要完整终端界面时提供 PTY 会话和终端视图；未识别提示在终端内手动处理，不能仅根据文本含有 yes/no 就自动生成可执行批准。

确认卡片展示 Agent 图标、账号、项目目录、会话、操作原文/变更详情和来源提供的可选动作。权限批准、问题回答和普通终端输入分别建模。只发送用户实际选择的动作，不自动选择“始终允许”。

每个请求绑定供应商、会话、连接世代和请求 ID；重复点击只生效一次，其他会话即使使用相同请求 ID 也不受影响。请求取消、连接中断、会话退出或过期后禁用操作，迟到回复不得作用于新请求。未回复时保持原 CLI 的等待/取消语义，不自动批准。

无法接管任意已运行终端的标准输入。外部会话必须通过可用的官方 Hook、桥接启动器或产品协议接入；如果当前产品只支持通知，则明确显示通知能力并提供回到原终端的入口。

## 6. 额度与账号数据

额度记录包含供应商、账号标识、模型/额度桶、数据来源、计量单位、已用/剩余值、总量（可缺省）、周期、重置时间、获取时间和状态。百分比、请求数、Token 和货币不能相互替代或跨产品相加。

状态分别为：可用、未登录、未安装、正在加载、数据过期、无权限、账号类型不支持、接口不支持和请求失败。没有数据表示未知，不能推算为 0% 或 100%。重置倒计时到零后等待实际刷新，不直接改为满额度。

发现当前 CLI 和用户指定的账号配置目录，支持同时列出多个明确配置的账号。账号切换后重新绑定采集源，避免串号；不会扫描其他系统用户的目录。

凭据留在原 CLI 或系统凭据存储中，前端仅接收账号展示信息及归一化额度。数据库保存设置、账号引用、额度快照和最小必要的交互状态，不保存明文 Token。账号读取接口不得触发模型推理、购买额度或消费重置权益。

刷新采用事件优先、轮询补充，支持手动刷新、请求合并、超时、退避和休眠唤醒后更新。具体刷新间隔、超时及数据保留周期由配置提供。

## 7. 模块和配置

- 桌面壳：窗口、托盘、快捷键和系统生命周期。
- Provider Registry：供应商身份、图标引用、适配器和能力描述。
- Account/Quota Service：账号绑定、额度采集、快照和刷新调度。
- Session Service：CLI 进程、PTY/JSON-RPC/ACP 连接和退出清理。
- Interaction Broker：确认请求状态、去重、回复路由和取消。
- Settings Store：SQLite 设置、迁移及外置配置导入。
- 前端：额度列表、确认卡片、会话视图和设置；通过受限 IPC 调用后台。

运行时用户设置存入 SQLite。进程级服务设置通过启动参数/环境配置提供。默认目录、服务端点及参数放在可外置覆盖的配置文件中，首次初始化时按需写入数据库；已存在的数据库设置优先。数据和配置目录使用系统标准位置，并允许用户指定，不能写死某位开发者的 home 路径。

供应商凭据只能发给对应供应商的已配置端点；端点变更应使旧凭据绑定失效。桥接只接受同一用户的已认证本机客户端，不能向网络暴露无认证的批准接口。

## 8. 跨平台行为

- Windows、macOS、Linux 均提供安装/运行入口，针对各自系统原生构建和测试。
- Linux 区分 X11/XWayland 与原生 Wayland。置顶、全局坐标及跨工作区行为受窗口管理器限制；提供能力提示和可用的恢复窗口入口，不能承诺在所有桌面环境都能强制置顶。
- 终端适配涵盖 Windows 可执行文件/脚本启动、含空格路径、Unicode、不同换行、窗口尺寸变化和子进程退出。
- 所有平台分别检查托盘可用性；没有托盘的桌面环境仍可从普通窗口恢复。
- 构建产物、代码签名和真实系统功能测试分别报告；仅生成 CI 配置不算已验证 Windows/Linux。

## 9. 实施顺序和验收

1. 完成桌面外壳、设置、供应商目录、离线图标及真实的空/错误状态。
2. 打通额度采集和交互请求的公共模型，完成 Codex、Claude Code 的端到端接入。
3. 验证 Gemini/Antigravity 的当前账号路径，逐个接入其余首批供应商；每个适配器记录支持的版本、账号类型、能力和验证结果。
4. 完成三平台打包、测试及双语使用文档；尚未验证的供应商/系统明确列出，不宣称完成全部需求。

必要验证覆盖：零值和缺失值、不同额度窗口、账号切换、过期数据、请求退避；批准/拒绝/问答、并发会话、取消、重复回复、退出和断线；配置迁移、优先级、数据脱敏；悬浮窗、托盘、键盘操作、图标离线加载与三平台真实启动。接口解析测试使用脱敏样本，真实账号联调与模拟测试分开记录。

## 10. 设计确认点

- 推荐采用 Tauri 2 技术栈和上述首批供应商目录。
- 推荐首版通过小工具或配套启动器管理 CLI，并对支持的外部会话提供官方 Hook 桥接。
- 额度支持以账号类型和真实接口为准，所有缺失/不可用能力在界面明确展示。
